**Recommendation:** Use a shebang on any executable script you want to run as `./script` rather than `python script.py`.

**What it does:** The kernel reads the first two bytes of a file on `execve()`. If they're `#!`, it treats the rest of the line as the interpreter to run, passing the script's path as an argument. So `#!/usr/bin/env python3` makes `./foo.py` work directly.

**Sources:** This is from my own knowledge, not fetched — the authoritative references are `execve(2)` (Linux man-pages) and the FreeBSD/macOS equivalent. Worth noting POSIX does *not* specify shebang behavior; it's a near-universal convention, not a standard.

**Conflicting information to be aware of:**
- `#!/usr/bin/env python3` vs. `#!/usr/bin/python3` — the `env` form respects `PATH`/virtualenvs (usually what you want); the absolute form is reproducible and avoids surprises in setuid/restricted contexts. Real disagreement, not a settled question.
- Argument handling differs by kernel: Linux passes everything after the interpreter as a *single* argument; some BSDs split on whitespace. Don't rely on multiple flags in a shebang.
- Line length is capped (~127 bytes on Linux, `BINPRM_BUF_SIZE`), which bites on deeply nested virtualenv paths.
