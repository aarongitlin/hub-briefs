**Memo: purpose of the shebang (`#!`)**

**Recommendation:** Use `#!/usr/bin/env python3` (or equivalent) on any script you want to execute directly.

**What it does:** When the kernel executes a file, it reads the first two bytes. If they're `#!`, it treats the rest of the line as the interpreter to run, passing the script path as an argument. Without it, `./script.py` fails or gets run by your shell as shell code.

**Sources** (cited from knowledge, not fetched this session):
- Linux `execve(2)` man page — "Interpreter scripts" section
- POSIX.1-2017 doesn't standardize `#!` at all; it's a de facto convention

**Conflicting information to flag:**
- *Portability of the mechanism itself:* POSIX explicitly leaves shebang behavior unspecified, so strictly speaking it's non-portable — yet every Unix-like kernel implements it. Practical advice and spec disagree here.
- *`#!/bin/python3` vs `#!/usr/bin/env python3`:* `env` finds the interpreter on `PATH` (good for virtualenvs, Homebrew, nonstandard installs); hardcoded paths are more predictable and avoid `PATH`-hijacking concerns. Security-hardening guides favor absolute paths; Python packaging guides favor `env`. Both positions are defensible.
- *Argument handling:* Historically Linux passed everything after the interpreter as a single argument, so `#!/usr/bin/env python3 -u` could break. Modern Linux (5.x+) still has quirks here; macOS/BSD differ. Avoid multiple args in the shebang.

**Caveat:** The shebang only matters if the file has the execute bit and is invoked directly. `python3 script.py` ignores it entirely.
